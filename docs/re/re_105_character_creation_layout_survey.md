## 2. 共用的繪製函式

創角畫面的程式在 overlay `0x64xxx～0x66xxx`，和背包、VIEW CHARACTER 共用同一批小函式。座標都由呼叫端傳入：

| 函式（檔案位移） | 內容 | 參數 | 我們的 tag |
|---|---|---|---|
| `0x64B57` | 性別＋種族 | x=`[bp+0E]`、y=`[bp+10]`；種族 x = x + (strlen(性別)+1)×6 | FFCD／FFCC |
| `0x64BF8` | 陣營 | x=`[bp+0E]`、y=`[bp+10]` | FFCB（**寫死** `ALIGNMENT_X/Y`） |
| `0x64D70` | AC 標籤 | x=`[bp+0C]`、y=`[bp+0E]` | FFE9 |
| `0x72B91` | 職業名稱 | x=`[bp+0E]`、y=`[bp+10]`、**名稱表=`[bp+14]`** | FF90～FF92 |
| `0x6511F` | 屬性標籤迴圈（`y + si×7`） | x=`[bp+0A]`、y=`[bp+0C]`；表 `DS:0EF2` | FFED（只在 (236, 8) 換中文） |
| `0x65168` | 屬性數值迴圈（`[0F64] + si×7 − 2`） | 全域 `[0F62]/[0F64]` | 無 |

### 職業名稱錯誤的原因

`0x643F5` 呼叫職業名稱函式時傳 `push 0x0ED2`，這是創角用的 8 格表
（1 CLERIC、2 DRUID、3 FIGHTER、4 GLADIATOR、5 PRESERVER、6 PSIONICIST、7 RANGER、8 THIEF；
後面接著 `STR:`～`CHR:` 與陣營名稱）。VIEW CHARACTER 傳的是 17 格的表。
解碼器的 `class_offsets` 一律用 17 格的編號，所以創角編號 3（戰士）變成牧師。
修正時要依 `[bp+14]` 判斷是哪張表。

## 4. 點擊範圍在 WIND-3011

- 創角視窗是 RESOURCE.GFF 的 WIND-3011。按鈕記錄是 `"BUTN"` + ID(4) + x(2) + y(2)，後面 18 bytes 都是 0，只存左上角。
- 執行期按鈕另有尺寸（`87E7:0014` 起的 x0,y0,x1,y1 與 `+2C` 的寬高）：屬性 50×5、陣營 82×7、HP 58×5、DONE 59×18。
  尺寸跟著按鈕走，所以移動左上角就等於移動點擊範圍。
- 屬性按鈕 ID `0x7DC`～`0x7E1`，點擊處理（`0x637F8`）用 `ID − 0x7DC` 當屬性索引，傳給 `5D80:0000`（另一個 overlay）。
- 屬性按鈕要點數值或標籤那一行；只點 ■ 左緣不一定有反應。`click_at` 太快時遊戲可能沒讀到，測試時用按下／放開分開送。
- 版面表的 ■ 只是裝飾，不是點擊範圍。

## 6. v127：右側職業清單與靈能／神術領域

### 6.1 這些字是 ICON 圖片

| 按鈕 ID ＝ ICON ID | 內容 | WIND |
|---|---|---|
| 2002～2009（`0x7D2`～`0x7D9`） | CLERIC～THIEF | 3011，(217, 10+8i) |
| 2038～2041（`0x7F6`～`0x7F9`） | P-KINESIS、P-METAB、TELEPATHY、P-PORTATION | 3012，視窗內 (7, 15+8i) |
| 2042～2045（`0x7FA`～`0x7FD`） | AIR、EARTH、FIRE、WATER | 3013，同上 |
| 2046／2047（`0x7FE`／`0x7FF`） | VIEW SPHERES／VIEW PSIONICS | 3012／3013，(7, 47) |

- ICON 格式：`u32 總長 + u16 格數 + u32×格數 偏移`；每格 `u16 寬 + u16 高`，接著逐列 `列號（由上往下）`＋若干 span，最後 `0xFF`。
  - span 是 `x, flags, 像素數, 碼長, RLE 碼`；flags `0x01` 表示 x+256，`0x80` 表示該列最後一段。
  - **像素數是遊戲實際使用的**：只能為每段連續的不透明像素各寫一個 span。整列寫成一段、像素數填 0 會畫成滿版直條紋（v124 的錯誤）。
  - opends 的解碼把列號當成由下往上，對 ICON 來說是顛倒的。
- 每張 ICON 3 格，只差文字顏色：0＝滑鼠停留（129）、1＝不可選（141，元素各有顏色）、2＝可選（27）。
- 按鈕的點擊大小＝ICON 大小；清單文字左邊留白 10px，給 ◆ 用。
- 遊戲會擦掉每個清單按鈕左側約 8px 放 ◆。英文切換鈕左邊沒留白，中文字會缺角，所以中文 ICON 左邊至少留 8px。

### 6.2 ◆ 與標題

- 職業清單的 ◆ 也是查表：`0x63BDA` 讀 `0338:019B`（檔案 `0x3E2DB`）的 8 格 y（原版 10、18…66，就是按鈕的 y），x 一樣固定 218。
  v127 漏改這張表，◆ 越往下越偏；v129 改成 4、14…74。
- 靈能／神術清單的 ◆ 由 `0xA0:3180` 畫在**固定 x=218**，y 取自遠端資料 `0338:01AB`（執行期 `40F8:01AB`，檔案 `0x3E2EB`）的 4 格表：103、111、119、127。
  所以這兩個清單只能維持單欄；v125／v126 試過兩欄，第二欄的 ◆ 會畫錯。
- 小標題：`0x67BD7`／`0x640E4` 在 (210, 88) 建立 WIND-3012／3013（surface 存在 `DS:0EA2`／`0EA6`），
  再用 `339E:016D` 在視窗內 (14, 6) 畫 `PSI DISCIPLINES`／`CLERICAL SPHERE`，不會解碼中文。

### 6.3 v127 的做法

- **ICON**（`creation_icon_layer.py`）：用建置時的 CJB1 字形（只取 `0xFE` 字，不含陰影）重畫 18 張 ICON，高 10px，保留每格顏色。
  文字來自 `fixed_ui_labels.csv`：職業沿用 `UI_class_*`；靈能用兩字版「念動／精神／感應／傳送」；元素「風元素」等；切換鈕「神術領域」／「靈能分類」。
- **WIND**：職業 (217, 4+10i)；靈能與元素 (7, 15+10i)；切換鈕移到標題右邊 (50, 3)。
- **EXE**：◆ y 表改成 103、113、123、133；兩個標題的參數改成 tag `FF8C`／`FF8D` redirect，
  解碼器從 `ui_text_creation_titles`（靈能分類／神術領域）解碼，畫在 (6, 3)。
- **GFF 驗證**：ICON 長度改變會更新 `GFFI-2`（ICON 索引），建置時允許它變動。
- 實測：職業選取／取消、牧師自動切到神術領域、元素改選（◆ 到第 4 列）、兩個切換鈕都正常。職業清單最後一行「小偷」略壓到框下緣（使用者同意）。
