## 2. 已定位的固定字串

以下全部是 EXE 檔案 offset，不是執行期實體位址；中文為待審草稿，尚未匯入正式 catalog。
容量及需求均包含結尾 NUL；需求使用每個中文字 3 bytes 的現有 Base94 transport 計算。

| 原文 | 檔案 offset | 草稿 | 原容量 → 需求 | 來源證據／限制 |
| --- | --- | --- | --- | --- |
| BACKPACK | `0x4A1B3` | 背包 | 9 → 7 | `0x6CF99` 的 `push 1853h`，物品格 hover 分支 |
| STR: | `0x4999B` | 力量: | 5 → 8 | 六項能力標籤指標表起於 `0x49852` |
| DEX: | `0x499A0` | 敏捷: | 5 → 8 | 同上 |
| CON: | `0x499A5` | 體質: | 5 → 8 | 同上 |
| INT: | `0x499AA` | 智力: | 5 → 8 | 同上 |
| WIS: | `0x499AF` | 智慧: | 5 → 8 | 同上 |
| CHR: | `0x499B4` | 魅力: | 5 → 8 | 同上 |
| `%C%C%CPSI:` | `0x4A3AC` | `%C%C%C靈能:` | 11 → 14 | 必須保留格式控制；另有相同原文字串，不能全域取代 |
| `AC: %2d` | `0x497C0` | `防禦: %2d` | 8 → 12 | 必須保留數值格式參數 |
| Bone | `0x4A109` | 骨製 | 5 → 7 | `0x40A84` 指標 `17A9:4356`（offset:segment）；材質上下文 |

能力標籤原字串緊鄰排列。直接放入兩個中文字會覆蓋下一個標籤，必須另設字串儲存區，
並確認所有消費者與指標修補，不可只通過行高檢查就匯入。

目前 mapping 預檢另發現 `敏`（U+654F）、`慧`（U+6167）未映射。
後續必須透過既有字庫建置流程分配 ID、產生銀行字形並驗證；只加 mapping 不代表
staging 的 C0–C5 已包含字形。此輪未變更 mapping 或 banks。

### BACKPACK 為何仍未直接翻譯

靜態反組譯追蹤：

```text
物品格分支選字串
  BOX / BAG / STORE / BACKPACK
    → 0x6CF72 共用呼叫點
    → 0x6E111 包裝函式
    → far call 0580:005C（檔案中的 thunk 目標）
    → 底部名稱列的共用文字處理路徑
```

`0x6E111` 轉送文字 far pointer、`0x2C06` 參數及 `DS:11A4` 的 far pointer。
BACKPACK 不經 `0x6E288` 的 NAME-ID 解碼入口；目前 FONT-local core 的輸入是 NAME ID，
不是任意字串指標。因此，即使「背包」能放入原有 9 bytes，也不能推定會顯示成中文。
下一個最小探針應處理這個單列字串，但先確認解碼入口、寬度計算、字形快取及重繪。

### 排除誤判

- EXE `0x4A516` 的 `DROP`，引用在 `0x70D1F`，附近流程涉及 EDIT NAME、DUAL、
  CAN'T DROP、DROP THIS CHARACTER?；不是已證實的物品欄 DROP 按鈕來源。
- `SPLIT` 沒有在 EXE 找到 ASCII 字串。來源仍未確認，不能據此斷言一定是圖片。
- 不對所有同名字串做搜尋取代，也不把尚未定位的按鈕標成已完成。

## 3. 行高約束與配置提案

座標使用遊戲原始像素，不使用視窗放大後的像素。底框約 `Y=173` 來自使用者 v55
截圖判讀，不是已定位的裁切常數；預檢的上緣 `Y=4` 也是配置假設，須實機確認。

| 區塊 | v55 起點／列距 | 中文配置提案起點／列距 | 以 10px 字高計算的末像素 |
| --- | --- | --- | --- |
| 六項能力 | 23／7 | 8／10 | 67 |
| PSI | 69／單列 | 72／單列 | 81 |
| AC | 83／單列 | 84／單列 | 93 |
| 最多七列武器／種族傷害 | 99／10 | **維持 99／10** | **168** |

能力如果留在 `Y=23`，只將列距增加成 10px，第六列會畫到 82，與原 PSI 區重疊。
提案因此獨立調整能力、PSI、AC，保留已驗收的武器區，並非再次整組上移。

檢查採含端點公式：`bottom = y + (rows - 1) * advance + glyph_height - 1`。
字形不能碰到下緣 173；重疊檢查不依賴輸入順序。測試也涵蓋「10px 字形仍用 7px
列距」及「只加大能力列距卻未重排」兩種失敗情境。

**上述只是垂直配置的算術通過，尚未修補或實機驗證。**
能力標籤與數字由不同路徑定位；標籤自身的換行方式仍需追蹤，不能只改數字的 `imul`。
兩字標籤加冒號的實際寬度、數字 X 起點、PSI 值以及底部名稱列的置中／裁切都還要確認。
不可用這份預檢宣稱完整 UI 已經能顯示中文。
