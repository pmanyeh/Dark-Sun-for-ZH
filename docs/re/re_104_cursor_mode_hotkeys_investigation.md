# re_104：遊標模式與熱鍵分派（操作改良的前置調查）

> 日期：2026-09-25。在 v106 上調查，只讀記憶體與靜態反組譯，沒有修改任何東西。
> 目的：替「遊標模式熱鍵」與「行走遊標兼任觀察」兩項操作改良找出修補點。

## 1. 使用者定案的設計

- **熱鍵**：空白鍵＝行走，`A`＝攻擊，`S`＝觀察。原本 `A` 的動畫開關改用 `T`（`F6` 本來就是同一個功能）。
- **非戰鬥時，行走遊標點到可觀察的東西，就當作觀察**。太遠時先走過去，再觀察。
- **觀察遊標點太遠的東西，也改成走過去再觀察**，不再只顯示「太遠」。
- 戰鬥中的操作不變。攻擊（含暴力開門）一律要明確選擇，不會自動變成攻擊。
- 右鍵循環保留。

## 2. 遊標模式變數

- **DGROUP `11B8`**（執行期 `4B7A:11B8`）就是目前的遊標模式。實機切換比對過：
  - 1＝行走，4＝攻擊，2＝觀察。
  - 5＝施法瞄準（`0x8448B` 設定）。
  - 3＝條件式模式，由 `4281:0043`／`4281:0048` 判斷，推測是「拿著物品／使用物品」的遊標，尚未確認。
- **`4C25`**：保存的模式。`1587:28DC` 會先把目前模式存到這裡再設定新模式，`1587:28FC` 再從這裡還原。

## 3. 相關函式（常駐）

> **段值的寫法**：EXE 檔案內 far call 的段值是「載入相對段」，執行期要再加上載入段 `0x824`。
> 換算公式：檔案位移 = `0x5400` + 載入相對段 × 16 + 偏移。
> 例如檔案裡的 `191F` 在執行期是 `2143`，DGROUP `4356` 在執行期是 `4B7A`。
> 下表列載入相對段，括號內是執行期段。
> re_102／handoff 的「執行期段 − 0x824」公式，其實就是這裡的載入相對段。

| 位址 | 檔案位移 | 作用 |
|---|---|---|
| `1587:2927`（`1DAB`） | `0x1D597` | `set_mode(m)`：`[4C25]=[11B8]=m`，再呼叫 `191F:0A99(m)` 換遊標圖示。只有同段的 near 呼叫 |
| `1587:28DC` | `0x1D54C` | 先存 `[4C25]=[11B8]`，再設定新模式 |
| `1587:28FC` | `0x1D56C` | 從 `[4C25]` 還原 |
| `191F:0A99`（`2143`） | `0x1F089` | 依模式設定遊標圖示 |
| `1587:01C7`（`1DAB`） | `0x1AE37` | 右鍵循環，參數是 24 bytes 的輸入事件（傳值），只讀 +0Ch／+0Eh 的滑鼠座標 |
| `3118:002E`（`393C`） | `0x365AE` | `get_mouse_position(&x, &y)`：INT 33h function 3，回傳 320×200 的畫面座標 |

**右鍵循環 `1587:01C7`**：

- **執行條件**：
  - `377E:0019` 是 0 或 1，或者 `[4B75]` ≤ 4。
  - `[0BC9]` == 1，推測是「地圖畫面可接受輸入」。
- 用 `[11B8]-1` 查 jump table `cs:0296`（檔案 `0x1AF06`）：

| 目前模式 | 目標 | 動作 |
|---|---|---|
| 1 行走 | `0x1AE77` | 設 4。`si = 0x1D66A(事件)`，算出近戰或遠程的圖示；呼叫 `2191:063D`，再呼叫 `4211:0061(si,1)` |
| 2 觀察 | `0x1AEA8` | `4281:0043()` 為真就設 3，否則走 `0x1AED4` |
| 3 | `0x1AED4` | 呼叫 `2191:063D`，設 1，再呼叫 `191F:0A99(1)` |
| 4 攻擊 | `0x1AE92` | 設 2。`si = 0x1D66A(事件)`，再呼叫 `191F:0A99(si)` |
| 5 施法 | `0x1AEB8` | 呼叫 `2191:063D`，設 1。接著呼叫 `191F:013F` 和 `4272:00B1(0)`，應該是取消施法瞄準 |

- **只寫 `11B8`、不寫 `4C25` 的地方**：右鍵循環直接寫 `[11B8]`，不經過 `set_mode`，所以不會更新 `4C25`。
- **方向鍵移動**（`0x1BB34`）：模式不是 1 的話，會先 `set_mode(1)`。所以原設計本來就有「移動時自動回到行走」的行為。
- **常駐呼叫者 `0x1B649`**：在某個條件下設模式 3，否則用 `1587:28DC` 設模式 2。

## 4. 熱鍵分派（overlay）

- **函式位置**：檔案 `0x71153`，overlay 段基底是檔案 `0x6FDD0`。
- **比對方式**：鍵值是「掃描碼<<8 | ASCII」，大小寫各一筆。
  - 用 `mov cx,21h; mov bx,1E4Bh` 迴圈比對 33 筆，對應的跳躍位址在 `cs:1E4B+42h`。
  - 沒有對到的鍵，交給 `0x7177D` 的第二層 `c`～`v` 表（`c e i o u v`）。

| 鍵 | 處理位址（檔案） | 作用 |
|---|---|---|
| Esc、Alt-X、Ctrl-C、F3 | `0x71669` | 選單／離開 |
| `1`～`4` | `0x712DD` | 切換角色（送出事件 7） |
| 空白鍵 | `0x712DD` | 共用切換角色的處理程式，送出事件 8。只在背包等四個畫面有作用，**地圖上沒有作用** |
| `A`、F6 | `0x715CD` | 動畫開關 `[11AC]`，顯示 `1CA7`／`1CB5` 訊息 |
| `Q` | `0x7161D` | 結束回合 |
| `W` | `0x7148B` | 等待 |
| `G` | `0x713EF` | 防守 |
| `H` | `0x71440` | 畫面置中到隊長 |
| `S`、`T`、`M`、`?`、`=` | `0x7117C` 等 | **除錯鍵**，受 `[11B0]` 控制，正常遊戲沒有作用 |
| Tab | `0x712CB` | 尚未確認 |
| F1、F2、F4、F5 | `0x714E5`、`0x7152F`、`0x71564`、`0x7158E` | 尚未確認 |

- **`S` 的除錯功能**：`[2C0:0357] += 1000`，推測是金錢。
- **`T` 的除錯功能**：把 `0x989680` 寫進每個隊員的資料，再呼叫 `0628:0057`。
- 改掉 `S`、`T` 會失去這兩個除錯作弊，正常遊戲不受影響。

## 5. v107 熱鍵實作（`--cursor-hotkeys`，需要 `--view-ui`）

- **EXE**（`view_ui_layer.CURSOR_HOTKEY_EXE_PATCHES`）：
  - `T` 的除錯處理程式在 `0x711D0`，前後的 overlay 重定位在 `711CD`、`711FD`。這裡改成 tag `FF87` redirect，回傳 IP 是分派函式的結尾 `1DD0`。
  - 分派表的跳躍位址（`0x71C5D` + 索引×2）：
    - 空白鍵、`A`／`a`、`S`／`s` 指向 stub（IP `1400`）。
    - `T`／`t` 指向動畫開關（IP `17FD`）。
- **FONT 核心 `cursor_hotkey_entry`**：
  1. 依按鍵決定目標模式：空白鍵＝1，`A`＝4，`S`＝2。
  2. 取得滑鼠位置，組出一個假的輸入事件，**反覆呼叫原版右鍵循環**，直到 `[11B8]` 等於目標為止，最多 4 次。
     - 這樣副作用、執行條件和模式 3 分支都和玩家按右鍵完全相同。
     - 如果某次呼叫後模式沒有改變，表示遊戲拒絕切換，就停止。
  3. 核心呼叫的常駐段以 `DS − 4356h` 當作載入段計算，不寫死執行期段值。
- **開啟視窗時**：`[11A4]` 是目前的視窗，地圖上是 0。
  - 空白鍵：`[11A4]` 不是 0 時，回到原本的處理程式（IP `150D`），保留它在背包等畫面的作用。
  - `A`、`S`：只在 `[11A4]` 是 0 時生效。
- **限制**：失去 `S`、`T` 兩個除錯作弊；`A` 不再能切換動畫，改用 `T`（F6 的原因見 §6）。

## 6. v107 實測與 v108 修正

v107 實測結果：`A`、`T` 正常；空白鍵沒有作用；`S` 會先顯示沙漏，移動滑鼠後才變成觀察遊標；F6 沒有作用。

- **空白鍵**：地圖的上游按鍵處理程式（常駐，檔案 `0x1B7E0`）有自己的 26 筆按鍵表，其中包含空白鍵，所以空白鍵不會送到 overlay 的熱鍵分派。
  - 上游表：值在 `1587:0FEB`，跳躍位址在 +34h。
  - 表裡有 `1`～`6`、`P`、`N`、空白鍵、F5、F6、F9、F10、方向鍵等。
  - 沒有對到的鍵走 `0x1BB92`：`[0BC9]` 是 1 時，在 `0x1BC36` 把事件轉送給 `4272:0020`，也就是 overlay 的熱鍵分派。
  - 空白鍵原本的處理（`0x1BB8A`）：呼叫 `4251:00D9`（overlay 第 22 段，檔案 `0x6B07D`），對四個隊員清掉角色資料 +21h 的位元 `20h`，然後結束。這個位元的用途還沒確認。
  - **v108 修正**：`0x1BB8F` 的 `jmp 1BC55` 改成 `jmp 1BC36`。空白鍵先做原本的動作，再轉送給熱鍵分派。
- **S 顯示沙漏**：這是原版的小毛病。右鍵循環從攻擊切到觀察時，把圖示代碼（`1777h`）傳給以「模式」為索引的 `191F:0A99`，超出範圍，就落到預設的沙漏 `177Ah`。
  - 用右鍵時，下一次滑鼠移動會重算圖示，所以看不出來。
  - **v108 修正**：核心在迴圈結束後，如果模式是 2，就呼叫 `1587:29FA(x,y)` 取得觀察圖示，再呼叫 `4211:0061(圖示, 1)`。這和「行走→攻擊」那一步設定圖示的方式相同。
- **F6**：上游表把 F6 導到 `0x1B81E`，那是受 `[11B0]` 控制的除錯功能，會呼叫 `191F:00F1` 和 `142F:0426`。所以正常遊戲裡 F6 本來就沒作用，overlay 表裡的 F6 項目永遠不會被用到。動畫開關只剩 `T`。
- **遊標圖示代碼**：
  - `1771` 行走、`1777` 觀察（有目標）、`1778` 觀察（沒有目標）
  - `1773`、`1774`：攻擊相關
  - `177A`：沙漏

## 7. v108 實測與 v109 修正

v108 實測：空白鍵、`S`、`A`、`T`，以及戰鬥中、背包裡、施法瞄準中的行為都正常。但**快速交錯按 A／S／空白鍵時，偶爾會閃退**。

- **推測原因：overlay 換出**。
  - 右鍵循環會呼叫 overlay 第 15 段（`4211:0061` set_cursor_icon）和第 26 段（`4281:0043`、`4281:003E`）。載入這兩段時，可能把熱鍵分派所在的第 25 段換出或移走。
  - 核心把「返回第 25 段」的 CS:IP 存在 DX:CX，不在任何 BP 框架裡，overlay 管理程式找不到，也就不會修正。返回後就跳進錯誤的程式碼。
  - 用滑鼠右鍵時，循環是從常駐程式呼叫的，所以沒有這個問題。
- **v109 修正**：呼叫過遊戲函式之後，核心不再返回第 25 段，而是自己執行分派函式的結尾，直接返回常駐的呼叫者：
  - `mov si,[bp-5Ch]; mov sp,bp; pop bp; retf`
  - 分派函式的 prologue 是 `push bp; mov bp,sp; sub sp,5Ah; push si`。
- **沒有呼叫遊戲函式的路徑**：照原本方式返回第 25 段，這些路徑是安全的，包括：
  - 其他按鍵
  - 開啟視窗時按 `A`、`S`
  - 開啟視窗時按空白鍵，會回到 IP `150D`
- **如果 v109 仍會閃退**，下一個懷疑對象是 FONT 資源區塊：
  - 核心在 FONT 裡執行，呼叫遊戲函式的期間，堆疊上有指向 FONT 的返回位址。
  - 如果 set_cursor_icon 載入遊標資源時觸發記憶體整理、搬動了 FONT，返回位址就會失效。
  - 屆時要改成：核心不呼叫遊戲函式，只負責準備好狀態，由常駐或 overlay 程式碼自己去呼叫。

v109 實測：使用者已經重現不出閃退。

## 8. 智慧遊標調查：地圖的滑鼠事件與左鍵分派

- **`1587:1F83`（檔案 `0x1CBF3`）註冊地圖視窗的事件處理函式**：
  - `1587:0B6E`：按鍵（§6）
  - `1587:1053`：滑鼠
  - `1587:0059`：另一個，尚未確認
- **滑鼠處理 `1587:1053`（檔案 `0x1BCC3`）**：事件 +0 是 5 時才處理，再用 +4 的子類型查 `cs:12D9` 的表。

| 子類型 | 處理位址 | 動作 |
|---|---|---|
| `08h` 移動 | `0x1BCF7` | 模式不是 3、5 時，`4211:0061(0x1D66A(x,y), 1)` 重算遊標圖示 |
| `40h` 左鍵按下 | `0x1BD46` | 地圖上（`[0BC9]`==1）時設 `[0BBF]=1`，再呼叫 `0x1B348(事件)` |
| `20h` 左鍵放開 | `0x1BF30` | `[0BBF]=0` |
| `100h` 右鍵按下 | `0x1BEF0` | 用 `[0BBD]` 防止連發，呼叫右鍵循環 `0x1AE37` |
| `80h` 右鍵放開 | `0x1BF38` | `[0BBD]=0` |

- **左鍵分派 `0x1B348`（`1587:06D8`）**：
  - 戰鬥中如果不是自己的回合，就不處理。
  - 用 `[11B8]-1` 查 `cs:0B64`（檔案 `0x1B7D4`）：

| 模式 | 位址 | 行為 |
|---|---|---|
| 1 行走 | `0x1B396` | **非戰鬥**（`377E:0019`==0）時跳到 `0x1B3CF`：`0x1B097(領隊[4979], 點擊位置)` 設定目的地，清掉 `[0BB2]`、`[0BB4]`，`0x1AC7A(領隊)` 為 0 時呼叫 `191F:01FF(領隊,1)`。**戰鬥中**：點到自己就開啟結束回合彈出框 `0x1DB1F`，否則照樣走 |
| 2 觀察 | `0x1B407` | 見下方 |
| 3 | `0x1B54F` | 使用拿著的物品。物件編號 < 4 是隊員 |
| 4 攻擊 | `0x1B67B` | |
| 5 施法 | `0x1B7A6` | |

- **觀察 `0x1B407` 的流程**：
  1. `obj = 0x1B32F(事件)`，也就是 `1DF3:2822(鏡頭 [1178],[117A], 點擊 x,y)`，結果存進 `[496E]`，找不到是 -1，這時呼叫 `191F:013F`，然後結束。
  2. **視線**：`0898:00A4(領隊格, 物件格)`，被擋住就顯示 `NO LINE OF SIGHT`（`DGROUP:0BF8`）。
     - 格座標是物件表 `[obj*32+669D]`／`[+669F]` 右移 4 位。領隊用 `3781:0369` 當索引。
  3. **距離**：`0898:000C(領隊格, 物件格)` 大於 20，就在 `0x1B53D` 顯示 `TOO FAR AWAY`（`DGROUP:0BEB`）。
     - 這兩個檢查都有 `3015:000B` 的亂數，但結果只在除錯旗標 `[11B0]` 開啟時才不同。正常遊戲一律擋下。
  4. **互動**：`191F:0135`，接著 `41F9:004D(obj, 物件x−鏡頭x, 物件y−鏡頭y)` 開啟資訊卡或直接執行唯一的動作。
     - 之後如果 `4281:0043()` 為真（拿起了物品），就 `set_mode_save(3)`。
- **物件表**：每筆 32 bytes，從 DGROUP `6697` 開始。`+0`／`+2` 是像素座標，`+6`／`+8` 是格座標×16。

## 9. v110 智慧遊標階段 A（`--smart-cursor`，需要 `--view-ui`）

- **EXE**（`view_ui_layer.SMART_CURSOR_EXE_PATCHES`，都在常駐段 `1587`）：

| 檔案位移 | 原本 | 改成 | 目的 |
|---|---|---|---|
| `0x1B47E` | `lcall 3015:000B`（視線被擋時的亂數） | `jmp 1B4EF` | 視線被擋 → 走過去 |
| `0x1B483` | 除錯判斷的死碼（18 bytes） | tag `FF88` redirect | stub |
| `0x1B4EA` | `lcall 3015:000B`（太遠時的亂數） | `jmp 1B4EF` | 太遠 → 走過去 |
| `0x1B4EF` | 除錯判斷的死碼 | `mov cx,BEEFh; jmp 1B483` | 標記「走過去」 |
| `0x1B7D4` | 左鍵模式表，模式 1＝`0726` | `0813`（stub） | 行走點擊先經過核心 |

  - `0x1B481`、`0x1B4ED` 的段值 word 有 MZ 重定位，所以保留原樣；它們在新 `jmp` 後面，是不會執行到的死 bytes。
- **FONT 核心 `smart_click_entry`（tag `FF88`）**：
  - `CX`＝`BEEF`：返回 IP `075F`（`0x1B3CF` 行走路徑），往點擊位置走。
  - 否則：
    - 戰鬥中（`377E:0019` ≠ 0）：返回 IP `0726`（原本的行走入口）。
    - 非戰鬥：呼叫 `1DF3:2822(鏡頭x, 鏡頭y, 點擊x, 點擊y)`。
      - 物件編號 ≥ 4：返回 IP `0797`（`0x1B407` 觀察路徑）。
      - 其他（沒有物件，或點到隊員）：返回 `0726`。
- **行為**：
  - 非戰鬥時，行走遊標點到 NPC、門、箱子：
    - 近：和觀察一樣，開資訊卡或直接開門。
    - 遠或被擋：往點擊位置走。
  - 觀察遊標也一樣：太遠或被擋時走過去，不再顯示 `TOO FAR AWAY`／`NO LINE OF SIGHT`。
  - 走到之後，要再點一次。

- **v110 閃退（已由 v111 修正）**：
  - 行走遊標點 NPC 會閃退。實機單步追蹤到核心呼叫 `1DF3:2822` 之後，CX、DX 都被改掉了：
    - Borland 的 far 函式不保存 CX、DX。
    - entry 把返回 CS 放在 DX 裡跨過了呼叫，結果返回到 `00B4:0797`。
  - 事實上，非戰鬥時的每一次行走點擊都會走到這裡，所以點地面也會閃退。
  - v111 改成在呼叫前 `push dx`，呼叫後才決定 CX。
  - **通則**：核心在呼叫遊戲函式時，只能相信 SI、DI、BP、DS 會被保留。

- **v111 實測**：不再閃退；點遠處的 NPC 會走到點擊當時該 NPC 的位置附近。
  - **問題**：觀察距離（≤ 20）內的物件，行走點擊會直接開資訊卡，玩家無法走到物件旁邊。例如上鎖的門，要站在旁邊才能用攻擊模式打破。
- **v112 修正**：行走點擊到物件時，只有**相鄰**的物件才開資訊卡，其他一律走過去。
  - 「相鄰」沿用攻擊圖示的近戰判斷（`0x1D7E5`）：`1A0A:2BA5(角色, 物件)` ≤ 1。
    - 大於 1 時，攻擊圖示再分成遠程 `1775`、無效 `1776`。
  - 觀察遊標的行為不變：距離 ≤ 20 且視線通就互動，否則走過去。

- **v112 實測**：可以走到門邊了。使用者決定做階段 B：預設走到物件旁邊之後自動互動，按住 Ctrl 點擊則只移動。

## 10. 移動指令與「走到了」（v113 階段 B 的依據）

- **角色資料 +21h 位元 `20h`**：非戰鬥時行走不會改變它（寫入中斷點沒有觸發），所以不能拿來判斷是否在移動。
- **每個角色的移動指令**：`3972:08A6 + 角色×13h`，執行期段是 `4196`。
  - `+0`／`+2`：目標格座標。「走向物件」時 `+0` 放物件編號。
  - `+4`：指令類型。`0` 閒置、`0Fh` 走到某格、`13h` 走向物件。
    - `13h` 只用在 `3972:[物件×3+0C36]` == 2（生物），而且 `1A0A:2E99` 找得到旁邊可站的格子時。
- **設定目的地 `0x1B097(角色, x, y)`**：
  1. 換算成格座標。
  2. 點到生物時：戰鬥中如果已經相鄰，就直接攻擊（`0x1DFF2`），否則指令改成 `13h`。
  3. 寫入指令，呼叫 `1A0A:0B0F(角色, 1)` 開始執行。
  4. `3972:[角色×1Ch+0377]` == FFh 時，顯示 `DGROUP:0BD9` 的訊息（走不過去）。
- **每一幀**：
  - `0x1C9DE`：非戰鬥時 `push cs; call 1C3C4`（`1587:1754`）。
  - `0x1C3C4`：一開始就 `1A0A:121D(270Fh)`，推進所有角色的移動。
  - 走到時，`0x208AE`（`1A0A:140E`）把指令類型清成 0，並把 `3972:[角色×1Ch+0377]` 設成 FFh。
- **Ctrl**：遊戲沒有擋掉 BIOS 的按鍵旗標。實機讀 `0040:0017`：平常是 `30`，按住 Ctrl 時是 `34`。

## 11. v113 智慧遊標階段 B

- **EXE 新增兩處**：
  - `0x1B4F5`：死碼的剩下 6 bytes，改成 `mov cx,BEF0h; jmp 1B483`。
  - `0x1C9DE`：near call 從 `1C3C4` 改成呼叫 `1B4F5`。
- **核心 `smart_click_entry` 依 CX 分成三種**：
  - **BEF0（每幀）**：
    - 條件：有待互動、走的人的指令類型已經是 0、`[0BC9]` == 1、距離 ≤ 1。
    - 條件都成立時，執行觀察流程的互動部分：`191F:0135`；`41F9:004D(物件, 物件x−鏡頭x, 物件y−鏡頭y)`；如果 `4281:0043()` 為真，就 `1587:28DC(3)`。
    - 然後尾端跳躍到 `1587:1754`。
    - 只要指令類型變回 0，不論有沒有互動，待互動都會清掉。
  - **BEEF（觀察遊標：太遠／視線被擋）**：沒有按 Ctrl 時，記下 `[4979]`、`[496E]` 為待互動，再走過去。
  - **其他（行走點擊）**：先清掉待互動。
    - 戰鬥中、按著 Ctrl、沒點到物件、點到隊員：照原樣行走。
    - 相鄰：觀察。
    - 不相鄰：記下待互動，然後走過去。

- **v113 實測**：自動互動、Ctrl、中途改點別處、走不到的目標、開卡片的穩定性，都正常。以 `022de66` commit。

## 12. v114 滑鼠懸停圖示

- **icon_at（`1587:29FA`，檔案 `0x1D66A`）的行走分支（`0x1D851`）**：
  - `si = 1771h`（腳印），再用 `find_object` 找滑鼠下的物件。
  - 有物件：直接返回腳印。
  - 沒有物件：用 `142F:00DC(格)` 檢查能不能走，不能走就改成 `1772h`（禁止）。
- **遊標圖示代碼**：`1771` 行走、`1772` 不能走、`1773` 近戰、`1774` 自己（攻擊模式）、`1775` 遠程、`1776` 無效、`1777` 觀察（有目標）、`1778` 觀察（沒有目標）、`177A` 沙漏。
- **EXE**：
  - `0x1BCA7`：上游按鍵表裡 F6 的目標從 `0BAE` 改成結尾 `0FE5`。F6 原本是受 `[11B0]` 控制的除錯指令。
  - `0x1B81E`：空出來的 F6 死碼改成 `mov dx,ax; mov cx,BEF1h; jmp 1B483`。
  - `0x1D86F`：`cmp ax,-1` 改成 `jmp 1B81E`。
- **核心 `smart_hover`**：物件編號由 DX 帶進來，entry 一開始先存到 AX。
  - 沒有物件：返回 IP `2C04`（`0x1D874`，原本的「能不能走」檢查）。
  - 有物件：返回 IP `2C26`（`0x1D896`）。非戰鬥、不是隊員、沒按 Ctrl 時，先把 SI 改成 `1777h`。
- **限制**：遊標圖示只在滑鼠移動時重算。所以滑鼠不動、只按下或放開 Ctrl 時，圖示不會馬上改變。

- **v114 實測**：懸停圖示正常，但行走遊標點遠處的靜態物件（石棺、草堆）時，角色不會移動。

## 13. v115 靜態物件與戰鬥中的觀察

- **原因**：行走流程 `0x1B097` 以點擊的那一格為目的地。
  - 生物：原版會改成「跟隨」指令 `13h`。
  - 靜態物件：目的地就是物件本身佔住的格子，走不過去。
- **`1A0A:2E99(物件, &x, &y, 角色)`**（檔案 `0x22339`）：
  - 用 `0x21F54` 取得物件大小，繞著物件掃一圈。`0x2067B` 回傳 0 表示該格沒被擋住。
  - 用 `0898:000C` 挑出離角色最近的格子，寫進 `*x`、`*y`（DS 相對的 near 指標）。找到就回傳 1。
- **核心 `smart_retarget`**：走向非生物物件前（`3972:[物件×3+0C36]` ≠ 2），在堆疊上借 4 bytes 呼叫 `2E99`。
  - 成功時，把這次左鍵事件的 `[bp+12h]`／`[bp+14h]` 改成那一格的畫面座標：`格×16+8−鏡頭`。
  - 這個事件是傳值的複本，只影響這一次點擊。
  - 行走點擊（不相鄰）和觀察遊標的「走過去」都會經過這裡。
- **戰鬥中的觀察**：v110～v114 在戰鬥中用觀察遊標點太遠或視線被擋的目標，也會走過去，會消耗移動力。v115 改回原版的訊息：
  - 兩個分支共用 BEEF 標記，所以用原版的距離測試重算一次：觀察者 `3781:0369` 到物件，`0898:000C` > 20。
  - 大於 20 返回 `0x1B53D`（IP `08CD`，`TOO FAR AWAY`），否則返回 `0x1B66F`（IP `09FF`，`NO LINE OF SIGHT`）。
