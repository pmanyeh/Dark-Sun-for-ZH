## 2. GPL-3 固定入口 `0x07C0` 是誤判，已移除該限制

re_43 以為出口轉場是由 EXE 直接呼叫 `GPL-3@0x07C0`，因此加上
`--require-fixed-entry GPL:3:0x07C0:0x2A`。實際路徑是：

```text
MAS-42@0x012C  move boxtrigger 28, 11, 5, 1, 1854(0x073E), 3, 0
GPL-3@0x073E   ... local sub 0x07C0
```

當年工具把 0x6A 的參數位置讀錯（前四個其實是座標，re_98 §33 已修正），所以查不到這個
呼叫者。比對 v20 可證實：出口程式已移到 `0x0754`，但 boxtrigger 仍指向 `1854`，落在
tport 指令的參數中間。v21 讓整段長度恢復原樣，碰巧也讓觸發器位址復原。現在編譯器會正確
修正 0x6A，全量編譯時不再傳 `--require-fixed-entry`，v4 中 MAS-42 已指向 `1876`
（`0x0754`）。

## 3. 編譯器擴充

### 3.1 `gpl string copy`（0x0A）

16 個區塊原本因為這個指令被整段跳過。MAS-99 用它寫入全域 UI 字串（`GSTR[5] =
"Goodbye."`，也就是舊待辦的「Goodbye. 選項」來源，不在 EXE 裡）；GPL-157 等區塊用它在
`LSTR` 中組選單選項。會被 `string compare` 比對的字串已確認安全：

- GPL-20：玩家打字輸入的猜字關鍵字（`honor`／`h`…），譯者本來就保留英文。
- GPL-85：`nada` 哨兵值三處譯法相同，比對結果不變。
- GPL-91：比對對象 `"Drakath"` 也出現在運算式裡，本來就沒被選進編譯清單。

### 3.2 選單內嵌標題

19 個選單把標題（例如 GPL-29 的 `"Do you drink the wine?"`）直接寫在第一個參數，
以前會讓整段編譯失敗。現在能比對到，但依第 4 節一律保留英文。

### 3.3 `GFFI-7`

MAS chunk（33 個）的索引。MAS-99 長度改變時它會跟著變，已加入允許清單（GPL 的索引是
`GFFI-8`，217 筆）。

## 4. 必須保留英文的字串（`withheld`，共 23 筆）

v86 第一版全部翻譯後，對話框無法關閉、上一句會接在新句後面，下方選單標題變成亂碼。

1. **引擎控制字**：`DSUN.EXE` `0x4A871` 附近有 `CLOSE`／`DEBUG`／`END` 比對表。每段對話
   結尾都是 `print GSTR[2]` + `print GSTR[3]`，引擎靠這兩個字關閉並清空對話框。
2. **選單標題**：下方選單標題的繪製程式沒有中文路徑。標題來源有 `GSTR[1]`（553 個
   選單）、`GSTR[4]`（12 個）、19 個內嵌字串。

編譯器改為把這些字串記錄在封包的 `withheld` 清單並保留原文，不再讓整段失敗。若將來要
翻譯選單標題，必須先修補 EXE 的標題繪製程式。

## 5. EBOX 換行：中文字之間可以斷行

**症狀**：每段譯文片段都從新的一行開始，行尾留下大片空白。

**原因**：EBOX 版面迴圈（`341D:030D..04A9`）只在空白處斷行。區域變數：

| 變數 | 意義 |
|---|---|
| `[bp-1Ch]` | 目前單字的起點（-1 表示沒有） |
| `[bp-24h]` | 是否在單字中 |
| `[bp-1Ah]` | 本行是否已有可斷點（≠ -1） |

超出寬度時，若本行有可斷點且正在單字中，就把整個單字搬到下一行；否則在超出的字元處
硬切。沒有空白的中文句子等於一個超長單字。

**修法**：每處理完一個 `^xy` 字，就結束單字並標記可斷點。原本 13 bytes 的 helper
（`EBOX:028A`）放不下，所以改成 `call far 147D:00FC` + `inc si` + 原本的比較，並新增一筆
MZ 重定位項目。

```text
147D:00FC  80 7E F6 5E     cmp byte [bp-0A],'^'
           75 0D           jne ret
           89 76 E6        mov [bp-1A],si
           83 4E E4 FF     or  word [bp-1C],-1
           83 66 DC 00     and word [bp-24],0
           46 46           inc si ×2
           CB              retf
```

已知限制：沒有避頭點規則，偶爾會有「，」「。」出現在行首。

## 6. INTRODUCE 選項「I'm <名字>」→「我是<名字>」

`DSUN.EXE` `0xD088`：`strcpy(DS:4285, 377E:0000 "I'm ")`，接著 `strcat` 角色名字。
`377E:0019` 起是執行中會用到的變數，無法原地加長，所以改為把 strcpy 的來源指到
`147D:015C` 的「我是」。`DS:4285` 到下一個變數 `DS:42C8` 之間有 67 bytes，放得下。
譯文定義在 `build_cjk_display_staging.py` 的 `INTRODUCE_PREFIX_ZH_TW`。

## 7. 句子接縫處多餘的空格

英文句子會拆成多段輸出（`"...I've "` + `"been in here awhile. "`），目錄依空白對齊規則
保留段落邊緣的空格，在中文裡就會出現「我已經在 這裡」。規則只在編譯時套用，目錄不改
（`tighten_cjk_join_spaces`）：

- 最後一個字是全形字（`>= U+2000`，含「…」「—」）時，去掉結尾空格。
- 只在 `print string` 中：單一個開頭空格且後面接全形字時去掉。
- 保留：選單兩格縮排、三格列表縮排、英數字旁的空格、句中空格。

共影響 6,837 句。

## 8. BAD GPL EXIT：GPL 記憶體池只有 10,000 bytes

**症狀**：跟 Trustee（GPL-146）說話時出現 `BAD GPL EXIT`。

**確認過程**：

| GPL-146 大小 | 結果 |
|---|---|
| 9,658（原版） | 正常 |
| 9,991（只翻開頭） | 正常 |
| 10,706（全翻） | BAD GPL EXIT |

執行期讀 `3FA5:0313`（檔案段 `3781:0313`）得到 `0x2710`。

**機制**：GPL／MAS chunk 都載入同一個池（指標 `3781:0255`，大小 `3781:0313`，16 個
slot，`0x9EF9` 配置、`0xA02A` 淘汰），載入時會在尾端補一個 `0x31`。條件是
`size + 1 < 池大小`。池由 overlay 啟動程式 `0x6A692`：
`push dword 10000; push 200; call far <init>` 設定。原版最大的 chunk 是 GPL-2（9,792）。

**修法**：`0x6A694` 改為 `0x3000`（12,288）。執行期讀回 `0x3000`；讀取修補前的舊存檔後
池大小仍是新值，所以存檔不會覆寫它。編譯器新增檢查：任何 chunk 大於
`GPL_MAX_CHUNK_BYTES`（12,286）就建置失敗。

原本超過上限的 6 段一併解決：GPL-146（10,706）、72（10,658）、7（10,466）、187
（10,358）、168（10,205）、52（10,036）。

**排除過的方向**：存檔保存的觸發器位址（新遊戲也會重現）、`GPLX`（只存名稱到編號的
對應）、選單指令長度（GPL-146 的 683 bytes 小於原版最大值 775）、存檔的 SAVE-1
（10,240 bytes，但內容不是池，只是巧合）。

## 10. 工具注意事項

- 在 Bash 的 heredoc 中用 Python 寫入含 `\x..`／`\0` 的原始碼，跳脫字元會被實際寫成
  控制字元。改用寫在暫存目錄的腳本檔，或用 `bytes((0x9A,))` 的寫法。
- DOSBox-X-AI bridge 的回應 id 錯位無法自行恢復，只能結束 `dosbox-x.exe` 再重開
  （09-18 交接第 2.7 條）。
