# re_107：片頭的兩張羊皮紙

> 2026-09-26。v139 首版會在第一張羊皮紙之後當掉；v140（`scratch_test/cjk_display_staging_v140_intro_scrolls_fixed`）修正，
> 使用者已實機確認兩張都正常。建置選項 `--intro-scrolls`，程式在 `tools/intro_scroll_layer.py`。

## 1. 位置

| | 英文開頭 | 資源 | 何時出現 |
|---|---|---|---|
| 第一張 | The once lush and beautiful world… | CINE.GFF `BMA 8` 影格 0 | 標題畫面**不要按鍵**，等星空、星球乾枯動畫播完（要等很久） |
| 第二張 | By order of the Mighty and Omnipotent King Tectuktitlay… | CINE.GFF `BMA 9` 影格 0 | 主選單 START GAME 之後 |

- 兩張都是 320×200 全畫面、完全不透明的影格，格式與 ICON 相同（re_105 §6）：每列有列號，
  接著是多個 span（x、flags、像素數、碼長、RLE 碼），`0xFF` 結束。原版把 320 點的一列拆成 241＋79 兩段。
- 英文字都只用**一個色號**：第一張是 205，第二張是 186。第二張的首字「B」也是 186。
- 第二張右下角的封蠟（色號 161～171）本來就畫在影格 0 裡。預覽時封蠟全黑，是因為用錯了調色盤，不是另外畫的。
- `BMA 8` 影格 1～73 是星空的小差分；`BMA 9` 影格 1 很大（225,769 bytes）。這些都不動。

## 2. 執行期調色盤

- CINE.GFF 的 PAL chunk 都只有一部分顏色，拼不出畫面上的顏色。
- 執行期的調色盤緩衝區在 `490F:0000`（6-bit DAC 值，768 bytes）。找法：暫停後用 `memory_search` 搜已知的三個相鄰顏色。
- 兩張羊皮紙都內建一段「墨色 → 羊皮紙」的漸層（原版用來畫陰影），反鋸齒時字的邊緣就用這段顏色：
  - 第一張：200～204 撕邊陰影、205 墨色（`28 12 0A`，紅褐）、206～231 漸亮到羊皮紙。
  - 第二張：105～135 羊皮紙（與 PAL 10 相同），172～185 漸層，186 墨色（`29 0F 07`，暗紅）。
  - 數值都寫在 `intro_scroll_layer.SCROLL1_PALETTE`／`SCROLL2_PALETTE`。

## 3. 做法

1. **擦字**：文字框內的墨色像素，改成附近（上下左右 7px 內）隨機一個羊皮紙色（第一張 214～231，第二張 121～131）。紙紋看不出修補痕跡。
2. **寫字**：微軟正黑體粗體（`C:/Windows/Fonts/msjhbd.ttc`）20px，先以 4 倍解析度畫，再縮小取得每點的覆蓋率。
   - 覆蓋率 < 0.1 的點不畫；其他點取「底色與墨色依覆蓋率混合」後最接近的調色盤顏色（只從第 2 節的漸層裡選）。
   - 字的位置：左 40、上 22、行距 21。
   - 使用者比較過的其他版本：Fusion Pixel 2 倍（太細）、正黑體黑白門檻（筆畫粗細不一）、正黑體點陣微調（乾淨但使用者偏好反鋸齒）。
3. **編碼**：`encode_frame` 用動態規劃求最短的 RLE（重複碼 2 bytes、直接碼 1＋n bytes），每段最多 241 點。
4. **放回**：`replace_frame0` 把新影格放進原本影格 0 的位置，不足的長度在結尾補零。
   整個 BMA 的長度、表頭、影格位址表、之後的所有影格都**逐位元組不變**。

譯文（使用者 2026-09-26 確認；第一張為了放進紙面，比初稿精簡）：

- 第一張：曾經青翠的亞薩斯，如今荒涼而致命。巫王統治各城邦，為追逐權力，碾碎一切生命與自由。在德拉吉，奴隸以無盡的死亡之舞，餵養巫王之力。
- 第二張：奉偉大全能的特克圖克特雷王之命，凡能持劍的奴隸，皆須在角鬥場中作戰。死亡，便是角鬥士為軟弱付出的代價。／競賽開始！

## 4. v139 當掉的原因

- 每個 BMA 的第一個 u32 用途不明：
  - 單格圖（BMP、`BMA 4`、`BMA 10`）時，它等於 chunk 長度。
  - 多格動畫時，它小於 chunk 長度，也不對齊影格邊界（`BMA 8` 是 65368，chunk 68598）。
- v139 的新影格 0 比原版大 1.7 KB，後面 73 格的位址全都往後移，這個 u32 卻沒改。
  結果第一張羊皮紙顯示完、開始播星空差分時就當掉了。
- 修正：最短 RLE 讓新影格都比原版小（第一張 43,238 對 44,064；第二張 42,587 對 43,314），再補零到原長度。
  `replace_frame0` 遇到新影格比原版大時會直接報錯。
- 如果之後要改其他動畫的影格，也照這個原則：**不要改變 chunk 內任何影格的位置**。

## 5. 建置

- `--intro-scrolls` 會從原版 CINE.GFF 取出 `BMA 8`／`BMA 9`，驗證 sha256 後替換，
  再把原版與成品的 CINE.GFF 全部展開，確認只有這兩個 chunk 不同（CINE.GFF 沒有 GFFI）。
- manifest 的 `intro_scrolls` 記錄來源與成品的 sha256。成品 CINE.GFF 與原版一樣大（3,088,376 bytes）。
- 依賴：Pillow、系統字型 `msjhbd.ttc`（找不到會報錯）。

## 6. 還沒做：片尾

- 使用者要先做片頭，片尾暫緩。片尾的兩首詩在 CINE.GFF 的 `BMP 10`、`BMP 11`（單格圖，header u32 等於 chunk 長度）。
- 名詞：「龍之剋星」使用者已同意。
- 工作人員名單、SSI、AD&D、公司標誌都**不翻**（使用者 2026-09-26 決定）。
- 做法可以沿用本篇：先抓執行期調色盤，確認字的色號與漸層，再重畫。單格圖不受第 4 節的限制，但保持同長度仍然最安全。
