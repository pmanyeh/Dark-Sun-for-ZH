## Files

- `dialogue_units.csv`: primary translator worksheet; one row per exact unique dialogue string.
- `dialogue_occurrences.csv`: every GPL/MAS use site, linked to a dialogue unit by `unit_id`.
- `localization_manifest.csv`: combined dialogue, GFF resource, and EXE-candidate worksheet.
- Matching `.json` files retain nested locations and unresolved LSTR candidate writers.

Existing non-empty translations in the CSV files are preserved when the generator is run again.
Exact source text is the deduplication key within each namespace. Leading and trailing spaces are preserved.
EXE entries are conservative heuristic candidates, have `status: needs_review`, and are not yet marked translatable.
Duplicate GFF values share one translation unit but retain every container/chunk location.

## CJK glyph inventory

`localization/cjk_mapping.json` is the append-only Unicode-to-CJK-ID registry.
Refresh it after translation edits without renumbering existing characters:

```powershell
python tools/cjk_localization_pipeline.py inventory
```

Build provisional standalone 16x15 glyph banks into an ignored working
directory. This TTF command is for pipeline testing only; it is not the final
ETEN bitmap-font source:

```powershell
python tools/cjk_localization_pipeline.py build-banks `
  --font C:\Windows\Fonts\NotoSansTC-VF.ttf `
  --output scratch_test\formal_cjk_pipeline

python tools/cjk_localization_pipeline.py verify-banks `
  --package scratch_test\formal_cjk_pipeline\cjk-bank-set.json
```

The intended release glyph source is a legally user-supplied ETEN 16x15 pair:
`STDFONT.15` for Han characters and `SPCFONT.15` for full-width punctuation.
These proprietary files are not included in the repository. The current TTF
banks prove the transport and loader but remain replaceable build artifacts.

The ETEN coverage and build path are already wired. They can be checked before
the proprietary files are available:

```powershell
python tools/cjk_localization_pipeline.py audit-eten
```

Once both files are placed in a local directory, build the release-source banks
without changing the mapping or runtime:

```powershell
python tools/cjk_localization_pipeline.py build-banks `
  --eten-dir D:\path\to\legal-eten-fonts `
  --output scratch_test\formal_cjk_eten

python tools/cjk_localization_pipeline.py verify-banks `
  --package scratch_test\formal_cjk_eten\cjk-bank-set.json
```

For an ETEN 3.53S ISO9660 image, extract only the required files to ignored
build storage first. The local image may have an incorrect filename; verify its
ISO volume label (`ETEN353S`) rather than trusting the extension:

```powershell
New-Item -ItemType Directory scratch_test\eten353_extracted
tar -xf path\to\ET353S.iso `
  -C scratch_test\eten353_extracted `
  FILES/STDFONT.15 FILES/SPCFONT.15 FILES/ASCFONT.15

python tools/cjk_localization_pipeline.py build-banks `
  --eten-dir scratch_test\eten353_extracted\FILES `
  --output scratch_test\formal_cjk_eten353_16x15
```

`Fonts/` is ignored in full so proprietary/user-supplied media cannot be
committed accidentally.

The mapping uses the runtime-proven printable-triple transport (`^` plus two
base-94 digits). The algorithmic resolver is runtime verified. Literal `^` is
forbidden, and `^^^` / ID 5795 is permanently reserved because the repeated
prefix sequence is unsafe at an engine line boundary.

Compile every non-empty UTF-8 translation into an auditable runtime transport
package (the output directory is ignored):

```powershell
python tools/cjk_localization_pipeline.py compile-catalog `
  --output scratch_test\encoded_catalog.json
```

Compilation preserves ASCII engine syntax byte-for-byte, including `%` format
parameters, TAB, and newlines. It fails with the CSV row and unit ID when text
contains NUL, literal `^`, or a non-ASCII character missing from the mapping.

## Safe SPIN GFF import

Compile translated `SPIN` units that occupy complete GFF chunks. The compiler
preserves each chunk's catalogued terminator (170 CRLF and 2 unterminated chunks
in the current catalog) and deliberately skips embedded `NAME` records:

```powershell
python tools/cjk_localization_pipeline.py compile-gff-text `
  --output scratch_test\spin_gff_import
```

Pack an isolated `RESOURCE.GFF` and verify the complete chunk set after reading
it back through `gff-cat`:

```powershell
python tools/cjk_localization_pipeline.py pack-gff-text `
  --package scratch_test\spin_gff_import\gff-text-replacements.json `
  --output scratch_test\spin_gff_verified_build\RESOURCE.GFF
```

The source game file is never overwritten. Verification requires every target
payload to match its package hash and every non-target resource chunk to remain
byte-identical; only the `GFFI-1` container index is allowed to change.

## Complete Chinese-display staging build

Build an isolated test installation from the clean game, the verified bank set,
and the SPIN replacement package:

```powershell
python tools/build_cjk_display_staging.py `
  --bank-package scratch_test\formal_cjk_pixel_aligned\cjk-bank-set.json `
  --spin-package scratch_test\spin_gff_import\gff-text-replacements.json `
  --output scratch_test\cjk_display_staging_v1
```

The playable builder requires the CJK bank height to equal the original
FONT-100 height (9 rows). It preserves the complete 8,299-byte FONT payload,
appends the runtime scratch record at its legal end (`0x206B`), patches a copied
`DSUN.EXE` with the package's fixed record size, stages `C0.BIN` through
`C3.BIN`, and verifies every RESOURCE chunk. Run `launch-dosbox-x.cmd` from the
resulting directory; it uses the original three configuration files, fixed
7000 cycles, and the required `DARKSUN.BAT` entrypoint.

The current safe builder does not accept a 15-row bank for a playable build.
Changing FONT-100's global height from 9 to 15 reduces the opening box from
four lines to two; when the overflow crosses consecutive GPL `print`
instructions the unmodified game draws `MORE` without constructing a reachable
next page, hiding later text. This rejects only the presently unsafe direct
global-height implementation—not 15-row rendering as a future design. The
15-row research path remains open for a paginator fix, independent raster and
layout heights, or larger/reflowed dialogue boxes.

## Safe variable-length GPL dialogue import

Select translated dialogue units explicitly. The compiler checks each catalog
source string against the exact disassembled instruction, encodes Traditional
Chinese through the append-only Base94 mapping, relocates all instruction offsets
and local branch targets, validates the rebuilt chunk with OpenDS `gpl-asm`, then
proves that every non-target `GPLDATA.GFF` payload remains byte-identical:

```powershell
python tools/compile_gpl_dialogue_patch.py `
  --unit-id DLG_f6c2fbaa84a9 `
  --unit-id DLG_13ab12eaff4a `
  --unit-id DLG_6294a22b2cbb `
  --unit-id DLG_67aa8858af43 `
  --output scratch_test\gpl_celgor_zh_v1
```

Pass the resulting package to the isolated staging builder:

```powershell
python tools/build_cjk_display_staging.py `
  --bank-package scratch_test\formal_cjk_fusion_10x9_v7\cjk-bank-set.json `
  --spin-package scratch_test\spin_gff_import_title_newline\gff-text-replacements.json `
  --gpl-package scratch_test\gpl_celgor_zh_v1\gpl-dialogue-patch.json `
  --output scratch_test\cjk_display_staging_9row_v7_celgor
```

The dialogue compiler currently accepts only resolved inline compressed strings
inside `GPL` or `MAS` chunks. Dynamic expressions such as the player-character
name stay as original GPL instructions and are not flattened into translated
text.
